# Response Format

Arc responses carry **no envelope**. The HTTP status says success or failure; the body is the
resource, a list, or an error. There is no `success` flag and no `data` wrapper around a single
document.

## Quick Reference

| Operation | HTTP | Status | Body |
|-----------|------|--------|------|
| **List** | `GET /resources` | 200 | `{ method, data: [...], page, limit, total, pages, hasNext, hasPrev }` |
| **Get** | `GET /resources/:id` | 200 | the document |
| **Create** | `POST /resources` | 201 | the created document |
| **Update** | `PATCH /resources/:id` | 200 | the updated document |
| **Delete** | `DELETE /resources/:id` | 200 | `{ message, id, soft? }` |
| **Error** | any | 4xx / 5xx | `{ code, message, status, details?, meta? }` |

## List (GET /resources)

`method` says which pagination produced the page, and decides the remaining fields:

```json
{
  "method": "offset",
  "data": [
    { "_id": "…", "name": "Product A", "price": 29.99 },
    { "_id": "…", "name": "Product B", "price": 49.99 }
  ],
  "page": 1,
  "limit": 20,
  "total": 42,
  "pages": 3,
  "hasNext": true,
  "hasPrev": false
}
```

| `method` | Fields |
|---|---|
| `offset` / `aggregate` | `data, page, limit, total, pages, hasNext, hasPrev` |
| `keyset` | `data, limit, hasMore, next` — pass `next` back as the cursor |

## Get, create, update

The document itself. A resource with optimistic concurrency (`concurrency: { versionField }`)
also sends `ETag: "<version>"`; send it back as `If-Match` on the update, and a stale one is
answered `412 arc.precondition_failed` — re-read and retry.

```json
{ "_id": "507f1f77bcf86cd799439011", "name": "Product A", "price": 29.99 }
```

## Delete

```json
{ "message": "Deleted successfully", "id": "507f1f77bcf86cd799439011" }
```

With the `softDelete` preset the body also carries `"soft": true`.

## Errors

Every error — thrown anywhere, from any plugin — has one shape, repo-core's `ErrorContract`:

```json
{
  "code": "arc.validation_error",
  "message": "Validation failed",
  "status": 400,
  "details": [
    { "path": "email", "code": "format", "message": "must be an email" }
  ]
}
```

- **`code`** — switch on this, never on `message`. The full vocabulary is catalogued in
  `@classytic/repo-core/errors` (`ARC_ERROR_CODES`, `ARC_REASON_CODES`, `ERROR_CODES`), so a
  client imports it from there without depending on arc.
- **`details[]`** — one entry per offending field (`path` is a dot-path). Body validation, missing
  multipart files and duplicate keys all use it, so one mapping covers every form.
- **`meta`** — structured, non-PII extras (`{ retryAfter }` on `arc.idempotency_conflict`).

## TypeScript

```typescript
import type { ErrorContract } from '@classytic/repo-core/errors';
import type { OffsetPaginationResult, KeysetPaginationResult } from '@classytic/repo-core/pagination';
```

`@classytic/arc-next` wraps all of this — list/detail hooks, `ArcApiError` with `fieldErrors` —
for React clients.

## OpenAPI / Scalar

Every response shape is in the generated OpenAPI spec at `/documentation`.
