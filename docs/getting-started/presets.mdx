# Presets

Reusable resource configurations. Add routes, middleware, and behaviors with a single line.

## Usage

```typescript
import { defineResource } from '@classytic/arc';

defineResource({
  name: 'post',
  presets: [
    'softDelete',                              // String form
    { name: 'ownedByUser', ownerField: 'authorId' },  // Object form with options
    'slugLookup',
    'multiTenant',
  ],
});
```

## Available Presets

### softDelete

Soft-delete instead of hard-delete. Adds `deletedAt` field and restoration routes.

```typescript
presets: ['softDelete']
// Or with custom field:
presets: [{ name: 'softDelete', deletedField: 'archivedAt' }]
```

**Added Routes:**

| Route | Permission Key | Handler Method |
|-------|----------------|----------------|
| GET /deleted | `deleted` | `getDeleted` |
| POST /:id/restore | `restore` | `restore` |

**Controller Implementation:**

```typescript
import { BaseController } from '@classytic/arc';
import type { IRequestContext, IControllerResponse } from '@classytic/arc';
import type { ISoftDeleteController } from '@classytic/arc/presets';

class ProductController
  extends BaseController
  implements ISoftDeleteController {

  async getDeleted(req: IRequestContext): Promise<IControllerResponse> {
    const products = await this.repository.findDeleted();
    return { data: products };
  }

  async restore(req: IRequestContext): Promise<IControllerResponse> {
    const { id } = req.params;
    const product = await this.repository.restore(id);
    return { data: product };
  }
}
```

### slugLookup

Lookup resources by slug instead of ID.

```typescript
presets: ['slugLookup']
// Or with custom field:
presets: [{ name: 'slugLookup', slugField: 'urlSlug' }]
```

**Added Routes:**

| Route | Permission | Handler Method |
|-------|------------|----------------|
| GET /slug/:slug | inherits `get` | `getBySlug` |

No such permission and no preset option: boot fails under `strictPermissions` (`preset-route-public-by-omission`); with strict off the route mounts public with an info log. A public route is stated with `allowPublic()`.

**Controller Implementation:**

```typescript
import type { ISlugLookupController } from '@classytic/arc/presets';

class ProductController
  extends BaseController
  implements ISlugLookupController {

  async getBySlug(req: IRequestContext): Promise<IControllerResponse> {
    const { slug } = req.params;
    const product = await this.repository.getBySlug(slug);

    if (!product) {
      throw new NotFoundError('Product', slug);   // from '@classytic/arc'
    }

    return { data: product };
  }
}
```

### tree

Hierarchical tree structures (categories, folders, org charts).

```typescript
presets: ['tree']
// Or with custom parent field:
presets: [{ name: 'tree', parentField: 'parentCategory' }]
```

**Added Routes:**

| Route | Permission | Handler Method |
|-------|------------|----------------|
| GET /tree | inherits `list` | `getTree` |
| GET /:parent/children | inherits `list` | `getChildren` |

No such permission and no preset option: boot fails under `strictPermissions` (`preset-route-public-by-omission`); with strict off the route mounts public with an info log. A public route is stated with `allowPublic()`.

**Controller Implementation:**

```typescript
import type { ITreeController } from '@classytic/arc/presets';

class CategoryController
  extends BaseController
  implements ITreeController {

  async getTree(req: IRequestContext): Promise<IControllerResponse> {
    const tree = await this.repository.getTree();
    return { data: tree };
  }

  async getChildren(req: IRequestContext): Promise<IControllerResponse> {
    const { parent } = req.params;
    const children = await this.repository.getChildren(parent);
    return { data: children };
  }
}
```

### ownedByUser

Ownership enforcement. Users can only update/delete their own resources.

```typescript
presets: [{ name: 'ownedByUser', ownerField: 'authorId' }]
```

**Behavior:**
- On update/delete, checks if `item[ownerField] === user._id`
- Returns 403 if ownership check fails
- Elevated scope (`kind: 'elevated'`) bypasses ownership check automatically

**No Additional Routes** - Adds middleware to update/delete operations.

**Example:**

```typescript
// Resource definition
defineResource({
  name: 'post',
  presets: [{ name: 'ownedByUser', ownerField: 'authorId' }],
  permissions: {
    list: allowPublic(),
    get: allowPublic(),
    create: requireAuth(),
    update: requireAuth(), // Only author can update
    delete: requireAuth(), // Only author can delete
  },
});

// Automatic ownership check on update/delete
// User A can only update/delete posts where post.authorId === userA._id
```

### multiTenant

Multi-tenant data isolation by organization.

```typescript
presets: [{ name: 'multiTenant', tenantField: 'organizationId' }]
```

**Behavior:**
- Automatically filters queries by `organizationId` (from `request.scope`)
- Injects `organizationId` on create
- Elevated scope bypasses tenant filter automatically
- Guards every route of the resource, in any preset order: a preset route gets what the CRUD route it maps to gets (`/slug/:slug` → `get`; `/tree`, `/search` → `list`; `/bulk`, `/:id/restore` → their write), so anonymous is 401 and no organization is 403 there too. A custom `handler` route gets the tenant filter. `tenantScope: true` adds body injection (and covers a `rawHandler` route, otherwise untouched); `tenantScope: false` opts a route out.

**Requires:** `organizationScoped: true` on resource definition

**Example:**

```typescript
defineResource({
  name: 'order',
  presets: [{ name: 'multiTenant', tenantField: 'organizationId' }],
  organizationScoped: true,
  permissions: {
    list: requireAuth(),
    create: requireAuth(),
  },
});

// Requests require x-organization-id header
// GET /orders with x-organization-id: org-123
// Automatically filters: { organizationId: 'org-123' }
```

### audited

Adds audit tracking (who created/updated).

```typescript
presets: ['audited']
```

**Behavior:**
- Sets `createdBy`, `updatedBy` fields from `req.user`
- Requires auth middleware to be active

**Example:**

```typescript
defineResource({
  name: 'document',
  presets: ['audited'],
  permissions: {
    create: requireAuth(),
    update: requireAuth(),
  },
});

// Automatic tracking
// On create: sets createdBy = req.user._id
// On update: sets updatedBy = req.user._id
```

## Permission Keys

Preset routes reuse the CRUD keys: `slugLookup` and `filesUpload` read inherit `get`; `tree`, `search` and `similar` inherit `list`; `softDelete` uses `list` (`/deleted`) and `update` (`/:id/restore`); `bulk` uses `create`/`update`/`delete`. A read route with nothing to inherit fails boot under `strictPermissions`.

```typescript
defineResource({
  name: 'category',
  presets: ['softDelete', 'tree'],
  permissions: {
    list: allowPublic(),   // also GET /tree and /:parent/children
    get: allowPublic(),
    create: requireRoles(['admin']),
    update: requireRoles(['admin']), // also POST /:id/restore
    delete: requireRoles(['admin']),
  },
});
```

## Combining Presets

Presets work together:

```typescript
defineResource({
  name: 'document',
  presets: [
    'softDelete',           // Soft delete with restore
    'slugLookup',           // Lookup by slug
    { name: 'ownedByUser', ownerField: 'userId' }, // Ownership
    'multiTenant',          // Org isolation
    'audited',              // Created/updated tracking
  ],
  organizationScoped: true, // Required for multiTenant
  permissions: {
    list: requireAuth(),
    get: requireAuth(),
    create: requireAuth(),
    update: requireAuth(),  // Only owner can update; also POST /:id/restore
    delete: requireAuth(),  // Only owner can delete
    // GET /slug/:slug inherits `get`; GET /deleted inherits `list`
  },
});
```

## Custom Presets

Register your own presets:

```typescript
import { registerPreset } from '@classytic/arc/presets';

registerPreset('timestamped', (options = {}) => ({
  name: 'timestamped',
  middlewares: {
    create: [setCreatedAt],
    update: [setUpdatedAt],
  },
}));

// Use it
defineResource({
  presets: ['timestamped'],
});

// Override an existing preset (e.g., replace built-in behavior)
registerPreset('softDelete', myCustomSoftDelete, { override: true });
```

**Note:** `registerPreset` throws if the name already exists unless `{ override: true }` is passed.

### Preset Result Shape

```typescript
interface PresetResult {
  name: string;
  // Function form: (permissions, controller) — `handler: controller.getStats`.
  // A method read this way is verified at boot.
  routes?: RouteDefinition[] | ((permissions, controller) => RouteDefinition[]);
  middlewares?: {
    list?: RouteHandler[];
    get?: RouteHandler[];
    create?: RouteHandler[];
    update?: RouteHandler[];
    delete?: RouteHandler[];
  };
  schemaOptions?: RouteSchemaOptions;
  controllerOptions?: { slugField?: string; parentField?: string };
}
```

## TypeScript Interfaces

Use preset interfaces for type safety:

```typescript
import { BaseController } from '@classytic/arc';
import type {
  ISoftDeleteController,
  ISlugLookupController,
  ITreeController
} from '@classytic/arc/presets';

class CategoryController
  extends BaseController
  implements ISoftDeleteController, ISlugLookupController, ITreeController {

  // TypeScript enforces these methods exist
  async getDeleted(req: IRequestContext): Promise<IControllerResponse> { ... }
  async restore(req: IRequestContext): Promise<IControllerResponse> { ... }
  async getBySlug(req: IRequestContext): Promise<IControllerResponse> { ... }
  async getTree(req: IRequestContext): Promise<IControllerResponse> { ... }
  async getChildren(req: IRequestContext): Promise<IControllerResponse> { ... }
}
```

## Bulk Operations

Adds `POST /bulk`, `PATCH /bulk`, `DELETE /bulk` routes for batch CRUD. Permissions inherit from the resource's `create`/`update`/`delete`.

```typescript
defineResource({
  name: 'product',
  presets: ['softDelete', 'bulk'],
  permissions: {
    create: requireRoles(['admin']),
    update: requireRoles(['admin']),
    delete: requireRoles(['admin']),
    // Bulk ops inherit these automatically
  },
});
```

**Routes:**

| Route | Body | Repository Method |
|-------|------|-------------------|
| `POST /products/bulk` | `{ items: [...] }` | `repo.createMany(items)` |
| `PATCH /products/bulk` | `{ filter: {...}, data: {...} }` | `repo.updateMany(filter, data)` |
| `DELETE /products/bulk` | `{ filter: {...} }` | `repo.deleteMany(filter)` |

DB-agnostic — works with any repository that provides `createMany`, `updateMany`, `deleteMany`. MongoKit provides these via `batchOperationsPlugin`.

**Options:**

```typescript
import { bulkPreset } from '@classytic/arc/presets';

presets: [
  bulkPreset({ operations: ['createMany', 'updateMany'], maxCreateItems: 500 }),
]
```

## Files Upload

Backend-agnostic file uploads. Takes any implementation of arc's `Storage` interface and registers three raw routes on the owning resource. Arc ships zero reference `Storage` adapters on purpose — the 50-line adapter belongs in your app source, next to the decisions that inform it (dedup strategy, multi-tenancy policy, CDN integration).

```typescript
import { defineResource } from '@classytic/arc';
import { filesUploadPreset } from '@classytic/arc/presets/files-upload';
import { s3Storage } from './storage/s3-storage.js'; // your ~50-line adapter

defineResource({
  name: 'file',
  prefix: '/files',
  crud: false, // preset owns every route
  presets: [
    filesUploadPreset({
      storage: s3Storage({ bucket: 'my-app' }),
      allowedMimeTypes: ['image/png', 'image/jpeg', 'application/pdf'],
      maxFileSize: 5 * 1024 * 1024,
      permissions: { read: allowPublic() }, // read inherits `get`; unset fails boot under strict
    }),
  ],
});
```

**Routes:**

| Route | Behavior |
|-------|----------|
| `POST /upload` | Multipart → `storage.upload()` → 201 `{ id, url, pathname, contentType, bytes, metadata? }` |
| `GET /:id` | Streams bytes back. Full HTTP Range support (`bytes=start-end`, suffix `bytes=-N`, open-ended `bytes=N-`) with `206 Partial Content` + `Content-Range` |
| `DELETE /:id` | 204 on success, 404 on already-absent |

**When to use:** persistent CRUD-over-bytes patterns — media libraries, avatars, attachments, document vaults.

**When NOT to use:** process-and-return flows like OCR, speech-to-text, image classification, content moderation, LLM analysis. These don't want an `id` or a `url` — they want the buffer in-memory for one-shot processing. Use arc's `multipartBody()` middleware + a raw route directly; it's about 10 lines and avoids forcing you to write a no-op storage adapter.

See the [Files Upload guide](./files-upload) for the full preset API, the `Storage` contract, four worked adapter examples (media-kit, raw S3, local FS, in-memory), and the `runStorageContract()` test suite adapter authors use to verify compatibility.

## Search (text + vector + embed)

Backend-agnostic routes for search engines: Elasticsearch, OpenSearch, Algolia, Typesense, Atlas $vectorSearch, Pinecone, Qdrant, Milvus, etc. Arc ships the routes + permissions + OpenAPI + MCP wiring; you bring the backend.

```typescript
import { searchPreset } from '@classytic/arc/presets/search';

// A — auto-wire from a repo that exposes search/searchSimilar/embed methods
// (e.g. mongokit repos with elasticSearchPlugin + vectorPlugin registered)
defineResource({
  name: 'product',
  adapter: createMongooseAdapter({ model: Product, repository: productRepo }),
  presets: [
    searchPreset({
      repository: productRepo,   // shorthand: methods auto-discovered
      search: true,              // POST /search  → productRepo.search(body.query, body)
      similar: true,             // POST /search-similar → productRepo.searchSimilar(body.query, body)
    }),
  ],
});

// B — external backend (no repo coupling)
searchPreset({
  search: {
    path: '/full-text',
    schema: { body: z.object({ q: z.string().min(1), limit: z.number().int().optional() }) },
    handler: (req) => elastic.search({ index: 'products', q: req.body.q }),
  },
  similar: {
    handler: (req) => pinecone.query({ vector: req.body.vector, topK: req.body.topK ?? 10 }),
    mcp: false, // skip MCP for this one
  },
  // Bespoke paths — anything that doesn't fit /search, /search-similar, /embed
  routes: [
    { method: 'GET', path: '/autocomplete', permissions: allowPublic(),
      handler: (req) => algolia.suggest((req.query as { q: string }).q) },
  ],
});
```

**Defaults per section:**

| Section | Path | Method | Permission fallback |
|---------|------|--------|---------------------|
| `search` | `/search` | POST | resource `list` (unset: boot error under strict) |
| `similar` | `/search-similar` | POST | resource `list` (unset: boot error under strict) |
| `embed` | `/embed` | POST | `requireAuth()` |

Auto-wired `search` and `similar` read under the same row scope as the resource's `list` (permission filters and, under `multiTenant`, the caller's organization), taken from the resource controller (`listScope`). `similar` passes it as the vector pre-filter, so each field must be a filter field on the index; `search` post-filters the rows the engine returns. A section with its own `handler` scopes its own rows.

Every field (`path`, `method`, `permissions`, `schema` — JSON Schema or Zod v4 — `mcp`, `summary`, `tags`, `operation`) is overridable per section. Zod schemas are auto-converted to JSON Schema (draft-7 for Fastify / AJV, openapi-3.0 for docs) with no `.toJSONSchema()` call required.

**MCP:** each section and each entry in `routes` accepts the same `mcp` field as regular route definitions (`false` to skip, `RouteMcpConfig` object for description/annotations). One resource's tools are namespaced as `{op}_{resource}` so many resources can share the same paths without collision.

**When to skip the preset:** one-off search endpoints — just use `routes: [{ ... }]` on `defineResource` directly.

## Best Practices

1. **Use presets for common patterns** - Don't reinvent softDelete, multiTenant
2. **Implement required controller methods** - Use TypeScript interfaces for type safety
3. **Define all permission keys** - Presets add routes that need permissions
4. **Combine presets thoughtfully** - multiTenant + ownedByUser work well together
5. **Test preset combinations** - Ensure middlewares don't conflict
