## Test App Factory

### createTestApp

Creates a Fastify app with Arc's test defaults, an in-memory MongoDB, an auth provider and a fixture tracker.

```typescript
import { createTestApp, type TestAppContext } from '@classytic/arc/testing';

let ctx: TestAppContext;

beforeAll(async () => {
  ctx = await createTestApp({ authMode: 'jwt' });
});

afterAll(async () => {
  await ctx.close(); // Cleans up fixtures, app and DB
});

// Use in tests:
const res = await ctx.app.inject({
  method: 'GET',
  url: '/health',
});
```

Options (`resources`, `db`, `connectMongoose`, `authMode`, `defaultOrgId`) and the returned context are documented in [Test App](./test-app).

**Defaults applied**: `preset: 'testing'`, `helmet: false`, `cors: false`, `rateLimit: false`, `underPressure: false`.

### createMinimalTestApp

Creates a bare Fastify instance without Arc plugins. Use for unit tests that don't need the full stack.

```typescript
const app = createMinimalTestApp();
app.get('/test', async () => ({ ok: true }));
await app.ready();

const res = await app.inject({ method: 'GET', url: '/test' });
expect(res.json()).toEqual({ ok: true });
```

## Resource Preloading

`loadResources()` works in production and most vitest setups, but it can fail when resources are evaluated through dynamic-import edge cases — Node `#path` subpath imports under tsx, transitive `.js → .ts` resolution inside nested `node_modules`, or modules that depend on top-level engine init. `preloadResources` (from `@classytic/arc/factory`) sidesteps those paths by feeding Vite's compile-time `import.meta.glob` result through arc's resource normaliser so every match flows through vitest's transform pipeline like a static import.

### preloadResources

Eager form — every resource is evaluated at import time of the preload file. Use this when resources don't need any prior bootstrap.

```typescript
// tests/setup/preload-resources.ts
import { preloadResources } from '@classytic/arc/factory';

export const preloadedResources = preloadResources(
  import.meta.glob('../../src/resources/**/*.resource.ts', {
    eager: true,
    import: 'default',
  }),
);
```

```typescript
// tests/integration/foo.test.ts
import { createApp } from '@classytic/arc/factory';
import { preloadedResources } from '../setup/preload-resources.js';

const app = await createApp({ resources: preloadedResources, auth: false });
```

The helper accepts both `{ import: 'default' }` glob results (values are the resource directly) and the default form (values are the full module — first export with `toPlugin()` wins). Throws with the offending path if any module doesn't yield a valid resource. Output is sorted by `resource.name` for deterministic registration order, matching `loadResources()`.

### preloadResourcesAsync

Lazy form — use when resources depend on prior bootstrap (engine init, account-model registration, etc.) and can't safely be evaluated at preload-file import time.

```typescript
import { preloadResourcesAsync } from '@classytic/arc/factory';

// Bootstrap first…
await initAccountingEngine();

// …then load the resources.
const resources = await preloadResourcesAsync(
  import.meta.glob('../../src/resources/**/*.resource.ts', { import: 'default' }),
);

const app = await createApp({ resources, auth: false });
```

The full recipe (including the Vite-specific reasoning + CI build-first alternative) lives in [factory.mdx](../production-ops/factory) under "Vitest + `loadResources()`: when to use `import.meta.glob`".

## Requests and auth

Send requests with Fastify's own `app.inject()`, and take auth headers from the session provider on the test context:

```typescript
ctx.auth.register('admin', { user: { id: '1', roles: ['admin'] } });

const res = await ctx.app.inject({
  method: 'GET',
  url: '/products?page=1&limit=10',
  headers: ctx.auth.as('admin').headers,
});

expect(res.statusCode).toBe(200);
```

See [Auth Sessions](./auth-session) for the JWT, Better Auth and custom providers.

## Mock Factories

### createMockRepository

```typescript
import { createMockRepository } from '@classytic/arc/testing';

const repo = createMockRepository({
  getById: vi.fn().mockResolvedValue({ _id: '1', name: 'Test' }),
  create: vi.fn().mockImplementation((data) =>
    Promise.resolve({ _id: 'new-id', ...data })
  ),
});

// All CRUD methods are pre-mocked:
// getAll, getById, create, update, delete
// Also includes preset methods: getBySlug, getDeleted, restore, getTree, getChildren
```

### createMockUser

```typescript
import { createMockUser } from '@classytic/arc/testing';

const user = createMockUser({
  roles: ['admin'],
  organizationId: 'org123',
});
```

### createMockRequest / createMockReply

```typescript
import { createMockRequest, createMockReply } from '@classytic/arc/testing';

const req = createMockRequest({
  user: { id: '1', roles: ['admin'] },
  params: { id: '123' },
  body: { name: 'Test' },
});

const reply = createMockReply();
```

### createMockController

```typescript
import { createMockController, createMockRepository } from '@classytic/arc/testing';

// Takes the repository; list/get/create/update/delete are bare `vi.fn()` mocks
const controller = createMockController(createMockRepository());
controller.list.mockResolvedValue({ data: [] });
```

## Database Helpers

### mongoMemoryDatabase

Starts an in-memory MongoDB (`mongodb-memory-server`) and connects mongoose to it. It is the default `database` factory of `bootModuleApp`; call it directly when a test needs only the database:

```typescript
import { mongoMemoryDatabase, type TestDatabase } from '@classytic/arc/testing';

const db: TestDatabase = await mongoMemoryDatabase({ replset: false });
// db.uri         connection string
// db.connection  the driver connection handle

// ... run tests ...

await db.teardown(); // disconnects and stops the server
```

Pass `replset: true` for a single-node replica set (transactions). A test that also needs an app gets the same database from `createTestApp({ db: 'in-memory' })`; see [Test App](./test-app).
